# Choosing the assistant's name

These pages call the assistant Alex, its default name, and you, its owner, Sam.

The assistant is called Alex unless `.env` says otherwise. To give it another name, set `AGENT_NAME` and restart the service and your Claude Code session (the channel reads the name when it starts). The name is said in the consent line, the chat notice, the prompts, the bot page and the logs, and the participant list shows `"<name> (<OWNER_NAME>'s AI assistant)"` unless `AGENT_BOT_NAME` says otherwise.

What makes a good name:
- **One word of letters, 3 to 20 long.** The rules read "Mary-Jane" as two words and the apostrophe in "O'Neil" as a possessive, so such a name would never be heard. Accents are fine but ignored ("José" and "Jose" are the same name), and letters English doesn't use (such as "ø") are refused: the speech model is English and writes English spellings.
- **Not an everyday word.** The rules for who is being spoken to look for words such as "will", "may", "so", "right" and "please", so a name that is one of them is refused: as "Will", the assistant would answer every "Will you share your screen?", and as "Right", "Right, please leave." said to a colleague would make it leave and delete the meeting record. Names that are also everyday words but not in the rules ("Mark", "Roger", "Grant", "Hope"), and forms of address and replies that people say to anyone ("Dude", "Boss", "Honey", "Sweet"), are allowed with a warning: as "Mark", "Mark the ticket as done, can you?" is answered, and as "Roger", "Roger, you can go now." said to someone else makes it leave and delete the meeting record. The warning comes from curated lists of a few hundred such words, not a dictionary, so a name it doesn't flag can still be a word people say. Other assistants' wake words ("Alexa", "Siri") and three-letter names get a warning too.
- **Not the name of anyone you meet with.** The assistant can't tell a colleague called Alex from itself: it answers questions meant for them, and "Alex, please leave" said to them would make it leave. Alex is a common name, so this matters for the default too.
- **Easy to hear.** Two or three syllables that don't sound like common words work best.

The participant-list name must say the assistant is an AI, as the consent line and the chat notice do: `AGENT_BOT_NAME` has to contain the word "AI" (for example `AGENT_BOT_NAME=Nova (Sam's AI assistant)`), and must not deny it ("Nova (not AI)", "non-AI", "not a bot or AI", "no longer AI", "0% AI", "AI-free"), or the service and the channel refuse to start. The default does. It should start with the name on its own, with the rest in brackets ("Nova (AI)", "Nova (Sam's AI assistant)"): people who only see the participant list will say "<what they read first>, please leave", and that is heard only when it is the assistant's name, so "Nova AI", "Nova-AI", "AI Nova" or "Sam's AI: Nova" gets a warning at start-up.

The service and the channel check the name when they start. Errors stop them, with the reason in the log (the channel then shows as a failed MCP server in Claude Code); warnings are logged and they start anyway. `npm run check` repeats both.

Then find what speech recognition makes of the name in real meetings. After a meeting, read its transcript in `data/transcripts/` (see [Minutes](minutes-and-data.md#minutes)): it is readable only by you, kept for `TRANSCRIPT_RETENTION_DAYS` (30 days unless set), and deleted at once if someone asked the assistant to leave or removed it, so there is nothing to read from such a meeting. The participants' lines are labelled `Speaker`; look at the ones that were said to the assistant, and see how speech recognition wrote the name in them. When it wrote the name another way:
- a spelling that is not an everyday word (for Alex: "Alec", "Aleks") goes in `AGENT_NAME_VARIANTS`, comma-separated. These count anywhere in a line, like the name, but never for "please leave". Like the name, a spelling must never be the name of anyone you meet with, or the assistant answers what is said to them. The start-up check and `npm run check-name` warn about a spelling that is an everyday word or a form of address ("dude", "boss": said to anyone);
- a mishearing that is an ordinary word (for Alex: "Ionics", "Elix") goes in `AGENT_NAME_MISHEARD`. These count only as the first word of a line, or after "hey", "hi", "OK", "okay" or "so", for leaving too. So a mishearing must never be the name of anyone you meet with: with "Mark" in the list, "Mark, you can go now." said to a colleague called Mark makes the assistant leave and delete the meeting record, which can't be undone (a missed "please leave" can simply be said again). The same goes for a form of address or a reply, whoever it is said to: with "dude" in the list, "Dude, you can go now." said to anyone makes it leave. The start-up check and `npm run check-name` warn about a mishearing that is an everyday word, a form of address or a reply, or a common first name; the lists are curated, so one they miss can still be someone's name or a word people say to anyone.

Copy only the spellings into `.env`, never lines of the meeting. These lists are only what you put in them: the service never learns words from meetings, which would keep something from them and could let a participant teach it a word that makes it leave. Alex comes with its own lists, used while `AGENT_NAME` is Alex and both lists are unset.

After each change, run `npm run check-name` to try the name and lists on the sample meeting lines, then restart the service and your Claude Code session:
```bash
npm run check-name                                   # the name and lists in .env
npm run check-name -- Nova --variants Novah --misheard Novel,Noble   # or --variants=Novah --misheard=Novel,Noble
```
It runs the start-up checks, with the participant-list name the service would use with that name (`AGENT_BOT_NAME` from `.env`, or the one made from the name), and prints what reading `.env` warns about (a renamed setting, say) with the other warnings. A name given on the command line comes with the lists given with it, and with `.env`'s own lists only when it is `.env`'s `AGENT_NAME` (otherwise it says they were not used). It then reads about 1,900 meeting lines (`test/fixtures/name-corpus.json`: every line the tests and reviews have used, written and as speech recognition gives it) with your name, spellings and mishearings, and lists every line that would be handled differently than with Alex, worst first: a line that would now make it leave, then lines it would now answer when nobody asked it, then the rest, each explained (for example `as "Will", "Will will say it now." is answered`). No differences means the rules read your name on these lines exactly as they read Alex. That is not an all-clear: the corpus only shows the lines it contains, so a word they don't use can still be heard in ordinary speech, and the warnings still stand. Add `--all` to list every difference.

A new name changes the fixed lines (the consent line names the assistant), so their audio is made again the next time the service starts, and the old files are removed. Until each one is made, it streams live.
